# ADR 007: API REST com Containerização Docker

## Status
✅ **Aceito** - Implementado em 04/06/2026

## Contexto
Necessidade de uma API REST para CRUD de produtos com containerização para garantir ambiente consistente entre desenvolvimento e produção.

## Decisão

### Arquitetura da API
Implementar API REST com Spring Boot em 3 camadas:

| Camada | Componente | Responsabilidade |
|--------|-----------|------------------|
| Controller | `ProductController` | Endpoints HTTP |
| Service | `ProductService` | Regras de negócio |
| Repository | `ProductRepository` | Acesso a dados |

### Endpoints

| Método | Endpoint | Função |
|--------|----------|--------|
| GET | `/products` | Listar produtos |
| GET | `/products/{id}` | Buscar produto |
| POST | `/products` | Criar produto |
| PUT | `/products/{id}` | Atualizar produto |
| DELETE | `/products/{id}` | Remover produto |

## Containerização com Docker

### Dockerfile (Multi-estágio)

```dockerfile
# Estágio de execução: utiliza uma imagem leve do JDK 21
FROM eclipse-temurin:21-jdk-alpine

# Define um diretório de trabalho temporário
VOLUME /tmp

# Copia o arquivo .jar gerado pelo Maven para dentro do container como 'app.jar'
COPY target/*.jar app.jar

# Expor a porta que a aplicação vai rodar
EXPOSE 8080

# Comando para executar a aplicação quando o container iniciar
ENTRYPOINT ["java", "-jar", "/app.jar"]
```


### Docker-compose 
```yml
version: '3.8'

services:
app:
build: .
container_name: product-api
ports:
- "8080:8080"
environment:
SPRING_DATASOURCE_URL: jdbc:h2:mem:productdb
SPRING_DATASOURCE_DRIVER_CLASS_NAME: org.h2.Driver
SPRING_JPA_DATABASE_PLATFORM: org.hibernate.dialect.H2Dialect
SPRING_JPA_HIBERNATE_DDL_AUTO: update
SPRING_H2_CONSOLE_ENABLED: "true"
```

## Explicação do Dockerfile

| Conceito | Descrição |
|----------|-----------|
| **Multi-estágio** | Reduz tamanho da imagem final (não inclui Maven) |
| **Alpine Linux** | Imagem leve (~200MB vs ~600MB) |
| **VOLUME /tmp** | Diretório temporário para Spring Boot |
| **EXPOSE 8080** | Porta da aplicação |

## Comandos Docker

### Build e Execução

```bash
# Build da imagem
docker build -t product-api .

# Subir containers
docker-compose up

# Parar containers
docker-compose down
```

### Gerenciamento de Containers
```bash
# Listar containers rodando
docker ps

# Ver logs da aplicação
docker-compose logs -f app

# Reiniciar containers
docker-compose restart

# Subir em background
docker-compose up -d
```

## Consequências

### Positivas

| # | Benefício | Descrição |
|---|-----------|-------------|
| 1 | Ambiente consistente | Mesmo ambiente entre desenvolvimento e produção |
| 2 | Isolamento de dependências | Cada serviço roda isolado sem conflitos |
| 3 | Escalabilidade horizontal | Fácil replicar containers para alta demanda |
| 4 | DataLoader automatizado | Carga de dados de teste automática ao iniciar |
| 5 | Portabilidade | Funciona em qualquer sistema com Docker instalado |

### Negativas 

| # | Desafio | Descrição |
|---|---------|-------------|
| 1 | Curva de aprendizado | Necessidade de aprender comandos e conceitos Docker |
| 2 | Consumo de recursos | Containers consomem memória e CPU adicional |
| 3 | Persistência de dados | Requer configuração manual de volumes para dados |
| 4 | Debug complexo | Análise de erros mais difícil que execução local |
