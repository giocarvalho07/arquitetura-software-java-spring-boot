# ADR-008: Implementação de Observabilidade e Monitoramento para API de Produtos

## Status

**Aceito** - 09 de Junho de 2026

## Contexto

A API de Produtos (api-arquitetura-example) necessita de um sistema completo de observabilidade para monitoramento em produção, incluindo:

- Métricas de performance e uso
- Tracing distribuído para requisições
- Health checks para disponibilidade
- Logs estruturados para debugging
- Relatórios de cobertura de testes

## Decisão

Implementaremos uma stack completa de observabilidade utilizando:

- **Spring Boot Actuator** - Health checks e métricas base
- **Prometheus** - Coleta e armazenamento de métricas
- **Jaeger** - Tracing distribuído
- **JaCoCo** - Cobertura de testes
- **Docker Compose** - Orquestração dos serviços

## Componentes da Stack

### 1. Spring Boot Actuator

- **Endpoints**: `/actuator/health`, `/actuator/metrics`, `/actuator/prometheus`
- **Health checks customizados** para Database e Gateway
- **Métricas** HTTP, JVM e Database

### 2. Prometheus

- **Coleta de métricas** em intervalos de 15s
- **Armazenamento** time-series
- **Queries** para análise de performance

### 3. Jaeger

- **Tracing distribuído** com sampling 100%
- **Suporte** OTLP e Zipkin
- **Visualização** de dependências entre serviços

### 4. JaCoCo

- **Cobertura mínima** de 80% para linhas
- **Relatórios** HTML e XML
- **Integração** com pipeline Maven

## Docker Commands

### Comandos Básicos

#### Subir a Stack Completa

```bash
# Build e start de todos serviços
docker-compose up -d --build

# Subir serviços específicos
docker-compose up -d app
docker-compose up -d prometheus
docker-compose up -d jaeger
```

#### Descer a Stack
```bash
# Parar todos serviços
docker-compose down

# Parar e remover volumes
docker-compose down -v

# Parar serviços específicos
docker-compose stop app
docker-compose stop prometheus
```


#### Gerenciamento de Containers
```bash
# Listar containers rodando
docker-compose ps

# Ver logs de um serviço
docker-compose logs -f app
docker-compose logs -f prometheus
docker-compose logs -f jaeger

# Executar comando no container
docker exec -it produto-api sh
docker exec -it prometheus sh
```

## Prometheus Queries Essenciais

### Métricas de Requisições HTTP
```promql
# Total de requisições por segundo
rate(http_server_requests_seconds_count[1m])

# Requisições por endpoint
sum by (uri) (rate(http_server_requests_seconds_count[1m]))

# Requisições por status HTTP
sum by (status) (rate(http_server_requests_seconds_count[1m]))

# Taxa de erro (5xx)
sum(rate(http_server_requests_seconds_count{status=~"5.."}[5m])) 
/ 
sum(rate(http_server_requests_seconds_count[5m]))
```


### Métricas de Performance
```promql
# Latência média por endpoint
rate(http_server_requests_seconds_sum[1m]) / rate(http_server_requests_seconds_count[1m])

# Percentil 95 de latência
histogram_quantile(0.95, sum by (le, uri) (rate(http_server_requests_seconds_bucket[1m])))

# Percentil 99 de latência
histogram_quantile(0.99, sum by (le, uri) (rate(http_server_requests_seconds_bucket[1m])))
```

### Métricas de Sistema
```promql
# Uso de memória heap (MB)
jvm_memory_used_bytes{area="heap"} / 1024 / 1024

# Threads ativas
jvm_threads_live_threads

# CPU usage
process_cpu_usage

# Uptime da aplicação (horas)
process_uptime_seconds / 3600
```


### Métricas de Banco de Dados
```promql
# Conexões ativas no pool
hikaricp_connections_active

# Conexões ociosas
hikaricp_connections_idle

# Tempo mínimo de conexão (ms)
hikaricp_connection_timeout_total
```

## Consequências

### Positivas

- ✅ **Visibilidade completa** da aplicação
- ✅ **Debugging facilitado** com traces
- ✅ **Métricas de performance** em tempo real
- ✅ **Alertas proativos**
- ✅ **Qualidade de código garantida** (80% cobertura)

### Negativas

- ❌ **Overhead de performance** com tracing (3-5%)
- ❌ **Complexidade operacional** aumentada
- ❌ **Consumo extra de recursos** (memória/CPU)

## Alternativas Consideradas

| Alternativa | Decisão |
|-------------|---------|
| ELK Stack vs Jaeger + Prometheus | Escolhido: Jaeger + Prometheus (menos recursos) |
| New Relic vs Prometheus | Escolhido: Prometheus (open source, sem custos) |
| JUnit vs JaCoCo | Escolhido: Ambos (JUnit para testes, JaCoCo para cobertura) |
